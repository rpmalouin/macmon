# A menu bar app (roadmap item 13)

A macOS app in `macos/` that puts the sampler in the menu bar: a status item with CPU, memory and
a load dot, and a popover dashboard with the metrics the TUI shows. It is fed by a C ABI in `ffi/`
(roadmap item 4), so the app, the TUI, `pipe` and `serve` all run the same sampler and cannot
drift apart.

No privileged helper and no sudo anywhere: the app is ad-hoc signed, the bundle is assembled from
`swift build` output by `scripts/app-build.sh`, and it starts at login from a LaunchAgent.

Each task is its own run of commits on `main`, ≤ 200 production lines (`make loc REF=origin/main`) excluding tests; stop
and report past that.

`main` carries the security-hardening fixes (`4e77214`, cherry-picked from the branch
`feat/security-hardening`); the app work builds on them.

## Behavior

The status item:

```
12% •        all clear      CPU scaled ratio below 40% and swap free
62% •        moderate       above 40%, or memory over 70%
91% •        heavy          above 75%, or memory over 85%
```

The popover (click), refreshed every interval:


- Rows whose data is unavailable are left out, not shown as zero: no fans on a fanless Mac, no
  power when the counters are missing (the VM case), no ANE when the counter is absent.
- The chips, the labels and the dot follow the system appearance; colors are semantic system
  colors, since the app has no terminal theme to follow.
- Right-click the status item: the same popover with a Settings section — interval (1 / 2 / 5 s),
  compact label, which sections show, launch at login. Stored in `UserDefaults`.
- The sampler runs on its own serial queue; the UI reads the last sample and never blocks on it.

The C ABI (`ffi/include/macmon.h`):

```c
void  *macmon_sampler_new(void);
char  *macmon_sampler_next(void *sampler, uint32_t duration_ms);
char  *macmon_sampler_soc_json(void *sampler);
void   macmon_sampler_free(void *sampler);
char  *macmon_procs_next(void *sampler, uint32_t top_n);
void  *macmon_procs_new(void);
void   macmon_procs_free(void *sampler);
const char *macmon_last_error(void);
void   macmon_free(void *ptr);
```

- Every `*_next` returns a NUL-terminated JSON string to be released with `macmon_free`, or NULL,
  in which case `macmon_last_error()` has the message. It never panics and never aborts.
- The JSON is the metrics document with the same field names as `pipe` — minus the deprecated v0.7
  aliases, which a new consumer does not need — plus `timestamp` as Unix epoch seconds (no chrono
  dependency in `ffi/`).
- A sampler belongs to one thread: created, sampled and freed on the same one.

## Decisions

- **In-process, not a subprocess or a daemon.** `macmon pipe -s 1 -i 100` takes 0.22 s wall per
  invocation with a fresh sampler each time, so a per-tick spawn is out; `serve` needs a listening
  port (its default is still `0.0.0.0`) and a daemon that can be down.
- **JSON C ABI, not a struct ABI.** `Metrics` is `Serialize` only and the `pipe` field names are a
  compat-guarded contract, so new fields cost the app nothing. A struct ABI (roadmap #59) would
  need a mirrored header and a `Deserialize` impl kept in step with every metrics change. Sample
  documents are a few KB at 1 Hz.
- **`ffi/` is a workspace member with `publish = false`**, so the published crate keeps its exact
  artifact shape and `--no-default-features` is untouched. This step provides item 4's ABI only; the
  dylib, XCFramework and bindings packaging stays in item 4.
- **SwiftUI for the panel, `NSStatusItem` for the item**, deployment target macOS 14. The threshold
  dot carries colour, which an attributed status-item title lets us set and test; a `MenuBarExtra`
  label's rendering is not ours to control. The popover's content is SwiftUI either way. Xcode 27.0
  is installed and active, which is what makes SwiftUI possible at all: under Command Line Tools
  alone the macro plugin `libSwiftUIMacros.dylib` is missing and `@State` fails to compile.
- **The shell is one step, not two.** The package, the FFI wrapper, the sampling loop, the label and
  the status item land together or the app cannot run: step 2 came to 258 production Swift lines,
  past the ~200 rule, and the popover host moves to step 3, where its content arrives.
- **`make loc` learns the app** (`scripts/loc.py` gains a `macapp` part over `macos/**/*.swift`),
  or the budget rule cannot see most of this work.
- **No `.xcodeproj`.** SwiftPM plus `scripts/app-build.sh` assembling `Macmon.app`, because a
  `.pbxproj` diff is unreviewable and the repository already builds everything from scripts and
  Makefile targets. `swift test` (XCTest) works with Xcode installed.
- **The Swift package takes the header through a small clang target** (`import CMacmon`), the
  header copied from `ffi/include/` by the build script so there is one canonical header. SwiftPM's
  `unsafeFlags` cannot express a repository-relative `-L` (verified: it resolves relative to a
  directory that is not the package root), so the script passes the absolute search path and
  `-lmacmon_ffi` on the `swift build` command line.
- **Ad-hoc signing, LaunchAgent for login.** The Mac has no valid signing identity, so ad-hoc it is;
  `SMAppService` and widget extensions want a stable identity, so the login item is a LaunchAgent
  plist in `~/Library/LaunchAgents` with `KeepAlive`, the same mechanism `serve --install` uses.
- **The app's build links the archive itself.** A Rust staticlib does not carry its `#[link]`
  attributes, so the caller passes `-framework CoreFoundation -framework IOKit -framework
  Foundation -lIOReport` (IOReport is Apple's private SDK stub). Verified from a C caller against
  the archive: the sampler runs, the document decodes, and its 25 keys are `pipe`'s minus the four
  deprecated v0.7 aliases.
- **Settings in `UserDefaults`, never in `~/.config/macmon.json`.** The TUI drops unknown fields
  when it saves, so the app's settings would be erased by any TUI run.
- **The process list needs `procs.rs` in the library** (task 5): it moves from `src/app/` to `src/`
  behind a `procs` feature that the `app` feature enables. Verified as a pure move — its imports
  are `core_foundation`, `libc` and `std` only, with no dependency on the CLI. `fds.rs` stays in
  `src/app/` unless an open-files view is ever wanted.
- **`panic = "abort"` stays** (the release profile is workspace-wide): a panic on the sampling path
  ends the app, so sampling failures are returned as errors and the LaunchAgent's `KeepAlive`
  restarts a dead app. The sampling path has no panicking calls today.
- **The widget is deferred**, and not only for signing: whether a sandboxed widget extension may
  subscribe to IOReport at all is unverified. Macmon's widget would sample
  `host_processor_info` / `host_statistics64` the way MacMonitor's does, and the dashboard stays
  the live view.
- CI keeps running `make check` and `make test` unchanged; the `macapp` targets are separate so a
  contributor without Xcode is not blocked.
